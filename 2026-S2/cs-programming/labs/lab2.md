# Лабораторная работа 2. Работа с Git

## Задание

Создать Git-репозиторий для хранения лабораторных работ курса

Операции с Git можно выполнять из терминала или через GitHub Desktop

## Удаленный репозиторий

Создать на GitHub или другом согласованном Git-хостинге пустой репозиторий с именем `cs-programming-labs`

Не добавлять через веб-интерфейс файлы `README.md`, `.gitignore` и лицензию

Репозиторий может быть публичным или приватным, но должен быть доступен преподавателю к моменту защиты

## Структура

Создать локальный каталог `cs-programming-labs`, инициализировать в нем Git и использовать ветку `main`

Итоговая структура основной ветки

```text
cs-programming-labs/
|-- .gitignore
|-- README.md
`-- lab1/
    |-- README.md
    |-- task1.py
    |-- task2.py
    |-- task3.py
    |-- task4.py
    `-- task5.py
```

Файл `.gitignore` должен содержать

```gitignore
__pycache__/
*.pyc
.venv/
.idea/
.DS_Store
```

## История изменений

### 1. Описание репозитория

Создать `README.md` со следующими данными

- Название дисциплины
- Фамилия и имя студента
- Учебная группа
- Таблица лабораторных работ со столбцами `Работа`, `Тема` и `Статус`

Добавить в таблицу ЛР 1 по теме `Основы Python` со статусом `В процессе`

Сохранить `README.md` и `.gitignore` коммитом

```text
docs: add repository description
```

### 2. Начало ЛР 1

Создать каталог `lab1` по правилам размещения работ из корневого README курса, добавить файлы заданий 1 и 2 из ЛР 1 и сохранить изменения коммитом

```text
feat: start lab 1
```

### 3. Завершение ЛР 1

Добавить файлы заданий 3-5 и сохранить изменения коммитом

```text
feat: complete lab 1
```

### 4. Публикация основной ветки

Связать локальный репозиторий с созданным удаленным репозиторием под именем `origin`

Отправить ветку `main` в удаленный репозиторий

### 5. Изменение в отдельной ветке

Создать от `main` ветку `docs/lab1-status`

В таблице `README.md` заменить статус ЛР 1 на `Выполнена` и сохранить изменение коммитом

```text
docs: mark lab 1 as completed
```

### 6. Параллельное изменение

Переключиться на `main`

В той же ячейке таблицы заменить статус ЛР 1 на `Готова к проверке` и сохранить изменение коммитом

```text
docs: request lab 1 review
```

### 7. Разрешение конфликта

Находясь в `main`, выполнить слияние ветки `docs/lab1-status`

В конфликтующем участке оставить статус `Готова к проверке` и удалить служебные строки Git

Завершить слияние коммитом

```text
merge: resolve lab 1 status
```

### 8. Завершение работы

Удалить локальную ветку `docs/lab1-status`

Отправить ветку `main` в удаленный репозиторий

На защите показать страницу репозитория, результат `git status` и граф истории из `git log --oneline --graph --all`

При использовании GitHub Desktop дополнительно показать разделы `Changes` и `History`
