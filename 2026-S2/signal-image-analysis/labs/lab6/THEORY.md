# Классификация изображений

## Изображение и класс

Классификация присваивает изображению одну из заранее заданных категорий. Например, входом служит фотография предмета, а выходом - класс «кружка» или «бутылка»

Метка - правильный ответ для конкретного примера. Компьютеру удобно хранить метки числами: кружка может иметь номер 0, бутылка - 1. Сами числа не выражают степень похожести. Важно сохранить соответствие номеров и названий

Классификатор определяет класс изображения целиком. Он не обязан находить границы предмета. Поиск прямоугольника вокруг объекта относится к детекции, а присвоение класса каждому пикселю - к сегментации

## Чему учится модель

Модель получает изображение и вычисляет оценки классов. Веса модели определяют, какие сочетания пикселей и признаков влияют на ответ. В начале веса случайные. При обучении они изменяются так, чтобы правильный класс получал более высокую оценку

Обучение с учителем требует пар «изображение - правильная метка». Например, путь dataset/mugs/photo.jpg может соответствовать метке класса mugs. Папка задает ответ при подготовке данных, но модель на входе видит пиксели, а не имя файла

Разнообразие примеров важнее количества почти одинаковых копий. Если все кружки сняты на белом фоне, а бутылки на черном, сеть может выучить цвет фона. Тогда высокая точность на похожих фотографиях не означает понимания формы предмета

## От пикселей к тензору

Тензор в PyTorch - многомерный массив чисел. Список яркостей имеет одну ось, таблица яркостей - две, цветное изображение - три. Тензоры можно передавать на GPU и использовать в вычислениях, для которых PyTorch автоматически находит градиенты

Цветное изображение обычно хранится как массив (H,W,3). Значения uint8 лежат от 0 до 255. Перед передачей в модель данные переводятся в float32 и делятся на 255

Все изображения в пакете должны иметь одинаковые размеры. Можно растянуть их до общей формы или вписать в квадрат с полями. Вписывание сохраняет пропорции предмета, но оставляет однотонные полосы. Выбранная обработка должна быть одинаковой при обучении и при последующих прогнозах

PyTorch Conv2d ожидает оси в порядке (B,C,H,W): число изображений, каналы, высота, ширина. Например, (16,3,128,128) означает пакет из 16 цветных изображений размером 128 на 128

```python
array = np.asarray(rgb_image, dtype=np.float32) / 255.0
array = array.transpose(2, 0, 1)
tensor = torch.from_numpy(array.copy())
```

transpose меняет порядок осей с (H,W,C) на (C,H,W). Он не поворачивает фотографию. DataLoader затем собирает отдельные тензоры в пакет с дополнительной первой осью

## Dataset и DataLoader

Dataset описывает, как получить одно изображение и его метку по номеру. Он может хранить только список путей и читать очередной файл при обращении, не загружая все изображения в память сразу

DataLoader берет несколько элементов Dataset и объединяет их в пакет, или batch. При batch_size=16 модель за один шаг получает до 16 изображений. Последний пакет может быть меньше, и его тоже нужно учитывать при оценке

Перемешивание train меняет порядок примеров между эпохами. Для validation и test перемешивание обычно не нужно: фиксированный порядок удобен для сопоставления файлов, правильных ответов и прогнозов

## Двумерная свертка

Взвешенная сумма получается, когда каждое число умножается на свой вес, затем произведения складываются. Например, 0.5*10+0.5*20=15

Conv2d применяет небольшой набор весов к участкам изображения. Ядро 3 на 3 рассматривает соседние пиксели, перемещаясь по строкам и столбцам. Для RGB учитываются все три входных канала. Одни и те же веса используются в разных положениях

Один набор весов создает одну карту признака. Если выходных каналов 32, слой создает 32 такие карты. Они уже не являются красным, зеленым и синим каналами. Каждая карта показывает реакцию на определенное сочетание входных значений

При обучении могут появляться реакции на границы, текстуры и более сложные формы. Однако конкретному каналу нельзя автоматически приписать понятный человеку смысл без исследования

## ReLU и уменьшение размера

ReLU заменяет отрицательные значения нулями, а положительные оставляет: ReLU(x)=max(0,x). Это нелинейное преобразование. Без нелинейностей последовательность линейных слоев оставалась бы одним линейным преобразованием

MaxPool2d с размером 2 на 2 выбирает максимум в каждом небольшом блоке. Например, из значений [1,3,2,0] остается 3. При шаге 2 высота и ширина карты уменьшаются вдвое

Так снижается объем дальнейших вычислений, но часть информации теряется. Очень мелкий объект может исчезнуть после нескольких уменьшений. Поэтому уменьшение размера не является бесплатным улучшением

## От карт признаков к оценкам классов

После нескольких блоков свертки и уменьшения остаются карты признаков. AdaptiveAvgPool2d приводит каждую карту к заданному размеру, например 4 на 4, усредняя значения в соответствующих областях. Тогда число признаков перед следующим слоем известно заранее

Flatten превращает их в одну последовательность чисел для каждого изображения. Полносвязный слой Linear складывает эти признаки со своими весами

Последний слой возвращает по одному числу на класс. Для двух классов ответ может иметь вид [2.0,-0.5]. Эти числа называются логитами. Они могут быть отрицательными и не обязаны суммироваться в единицу

Класс с наибольшим логитом становится прогнозом. Softmax переводит логиты в положительные значения с суммой 1. Для [2.0,-0.5] получатся примерно [0.92,0.08]

Эти значения удобно показывать как уверенность модели среди известных классов. Но 0.92 не гарантирует 92% вероятности правильного ответа в реальном мире. Даже незнакомому объекту модель обычно назначит один из известных классов

## Функция потерь и обновление весов

CrossEntropyLoss сравнивает логиты с правильной меткой класса. Ошибка мала, когда модель сильно выделяет правильный класс, и велика, когда уверенно выбирает другой

Для одного примера смысл ошибки можно выразить как -log(p), где p - значение softmax для правильного класса. Если p=0.9, ошибка около 0.105. Если p=0.1, ошибка около 2.303

В PyTorch в CrossEntropyLoss передаются исходные логиты и целые номера классов. Отдельный softmax перед loss не нужен, он уже учтен внутри вычисления. Для вывода уверенности softmax применяется отдельно. [CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)

Градиент показывает, как небольшое изменение каждого веса влияет на ошибку. backward вычисляет эти производные, а optimizer.step обновляет веса. Перед шагом старые градиенты обнуляются через optimizer.zero_grad

Для простого градиентного шага новое значение веса равно старому минус learning_rate*gradient. Например, вес 0.5, градиент 2 и learning rate 0.01 дают 0.48. Положительный градиент означает, что небольшое увеличение веса повышает ошибку, поэтому шаг идет в сторону уменьшения. Это локальное направление, а не гарантия достижения лучшего решения

Adam тоже использует градиенты, но дополнительно учитывает историю их значений и подбирает масштаб обновления для разных весов. Поэтому его шаг не обязан совпадать с этим простым числовым примером

Эпоха - проход по всему train. Если в нем 160 изображений, а batch_size=16, одна эпоха состоит из 10 шагов. Learning rate задает масштаб обновления весов

## Разделение данных

Train используется для изменения весов. Validation помогает выбрать настройки и состояние модели. Test применяется для итоговой оценки после выбора

Изображения должны быть независимыми между наборами. Одна фотография с другим размером, соседние кадры ролика и несколько почти одинаковых снимков могут давать утечку данных. Модель фактически уже видела очень похожий объект в том же окружении

Поэтому серии связанных изображений либо целиком относятся к одному набору, либо сокращаются до независимых примеров до случайного разбиения. Проверка точных дубликатов помогает найти копии, но не заменяет просмотр похожих снимков

Разбиение по классам сохраняет представительство каждой категории. Например, 100 изображений класса можно разделить на 70 train, 15 validation и 15 test. Фиксированный seed и сохраненный список файлов позволяют повторить эксперимент

## Переобучение

Переобучение возникает, когда модель хорошо подстраивается под train, но хуже переносит найденные закономерности на новые данные. Типичный признак: train loss уменьшается, а validation loss после некоторого момента растет

Для итоговой проверки выбирается состояние с лучшей validation loss. Больше эпох не всегда означает лучшее качество. Test нельзя использовать для постоянного выбора удачных настроек

Dropout во время обучения случайно обнуляет часть внутренних значений, уменьшая зависимость от отдельных признаков. В режиме model.eval он выключен. Поэтому перед проверкой режим модели нужно менять явно

Аугментация создает допустимые вариации обучающих изображений, например отражение или небольшой поворот. Она применяется только к train и не должна менять смысл класса. Для цифр или текста некоторые отражения недопустимы

## Accuracy и матрица ошибок

Accuracy - доля правильных ответов. Если правильно классифицированы 18 из 20 изображений, accuracy=0.9. На маленьком test один ответ заметно меняет процент, поэтому рядом указывается число примеров

Для сравнения полезен простой прогноз наиболее частого класса train. Если 90% тестовых изображений относятся к одному классу, постоянный ответ может дать высокую accuracy без анализа изображений

Матрица ошибок показывает, какие классы путаются. В принятой записи строки соответствуют правильным классам, столбцы - предсказанным. Диагональ содержит правильные ответы, остальные клетки - ошибки

Высокая общая accuracy может скрывать плохой результат редкого класса. Просмотр самой матрицы и конкретных ошибочных изображений помогает отличить проблемы данных от недостатка обучения

## Сохранение и новый прогноз

Для повторного запуска нужны веса, архитектура, размер входа, правила обработки и порядок классов. Если поменять соответствие номеров названиям, правильный числовой прогноз будет подписан неверно

Дополнительное изображение обрабатывается так же, как обучающие: ориентация, RGB, размер, масштаб чисел и порядок осей. Перед прогнозом включается model.eval, производные отключаются через torch.no_grad

Классификатор с закрытым списком классов не умеет сам объявить новый класс. Необычный фон, другой ракурс или совершенно посторонний предмет требуют осторожной интерпретации ответа. [Dataset и DataLoader](https://docs.pytorch.org/tutorials/beginner/basics/data_tutorial.html)
