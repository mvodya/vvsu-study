# Лабораторная работа 13. Синхронизация

## Задание

Разработать программу для моделирования сортировочной станции грузовых контейнеров

На станции есть четыре складские зоны:

```text
A
B
C
D
```

В каждой зоне хранится набор контейнеров. Для контейнера необходимо хранить:

- идентификатор
- вес
- тип груза

Исходное состояние станции создать в программе. В каждой зоне должно быть не менее 20 контейнеров

Несколько worker threads одновременно выполняют операции станции:

- принимают новые контейнеры в зону
- перемещают контейнеры между зонами
- выдают контейнеры со станции
- обновляют общую статистику операций

Для каждого worker thread подготовить собственный список заданий. Задание содержит тип операции, идентификатор контейнера и нужные зоны. Достаточно создать задания непосредственно в программе

Содержимое каждой зоны является общим изменяемым состоянием. Доступ к зоне должен быть защищен `std::mutex`. Код, который читает или изменяет содержимое зоны, должен находиться в critical section

Для простых счетчиков использовать `std::atomic`. Атомарными должны быть как минимум:

- количество принятых контейнеров
- количество перемещенных контейнеров
- количество выданных контейнеров
- количество неуспешных операций

Неуспешные операции должны записываться в общий журнал. Доступ к журналу из разных потоков должен быть защищен отдельным mutex

Ключевая операция станции - перемещение контейнера между двумя зонами. Перемещение должно изменять две зоны как одну логическую операцию: контейнер удаляется из исходной зоны и добавляется в целевую зону

Операция перемещения должна безопасно блокировать две зоны. Для этого использовать `std::scoped_lock` или единый порядок блокировки mutex для зон. Сценарии `A -> B` и `B -> A`, выполняемые в разных потоках, не должны приводить к deadlock

Для операций, где требуется заблокировать только одну зону, использовать `std::lock_guard` или `std::scoped_lock`

Программа должна запустить несколько worker threads через `std::thread` или `std::jthread`. Если используется `std::thread`, каждый созданный поток должен быть завершен через `join`

После завершения всех потоков программа должна вывести:

- количество worker threads
- количество контейнеров в каждой зоне
- общий вес контейнеров в каждой зоне
- значения атомарных счетчиков операций
- список неуспешных операций с причиной
- итоговое количество контейнеров на станции

Программа должна корректно обрабатывать:

- попытку переместить отсутствующий контейнер
- попытку выдать отсутствующий контейнер
- попытку переместить контейнер в ту же зону
- пустой список заданий у worker thread

## Требования

- Названия переменных, функций, типов и других сущностей программы должны быть осмысленными и записываться на английском языке без транслитерации
- В программе должны быть четыре складские зоны `A`, `B`, `C` и `D`
- В программе должно быть несколько worker threads, которые одновременно выполняют задания станции
- Для защиты содержимого складской зоны использовать `std::mutex`
- Код чтения или изменения зоны должен выполняться внутри critical section
- Для блокировки одной зоны использовать `std::lock_guard` или `std::scoped_lock`
- Перемещение контейнера между двумя зонами должно быть защищено от deadlock через `std::scoped_lock` или единый порядок блокировки mutex
- Для счетчиков операций использовать `std::atomic`
- Общий журнал неуспешных операций должен быть защищен mutex
- В программе должны использоваться `std::thread` или `std::jthread`
- Для `std::thread` все созданные потоки должны завершаться через `join`
- Программа должна быть грамотно разбита на модули и содержать как минимум один `.hpp` файл и два `.cpp` файла. Допускается использовать больше файлов
- Для заголовочных файлов использовать `#pragma once`
- Программа должна компилироваться и выполняться без ошибок
- Студент должен понимать написанный код, уметь обосновать свое решение и отвечать на вопросы во время защиты лабораторной работы

Минимальный набор операций:

- прием контейнера в зону
- выдача контейнера из зоны
- перемещение контейнера между зонами
- выполнение списка заданий worker thread
- формирование итогового отчета станции
