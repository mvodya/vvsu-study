# Лабораторная работа 15. Behavioral patterns

## Задание

Разработать программу для моделирования работы робота-пылесоса

Путь к карте помещения передается через аргумент командной строки

Пример запуска:

```text
./robot_cleaner room.txt
```

Карта находится в текстовом файле и может иметь любой прямоугольный размер. Каждая строка файла - один ряд клеток помещения

Использовать следующие символы карты:

| Символ | Значение                 |
| ------ | ------------------------ |
| `#`    | препятствие              |
| `.`    | свободная клетка         |
| `*`    | загрязненная клетка      |
| `R`    | начальная позиция робота |

Например:

```text
##########
#..*.....#
#...R....#
#.....*..#
##########
```

В карте должна быть ровно одна начальная позиция робота. Робот может перемещаться только по свободным и загрязненным клеткам. Через препятствия робот проходить не может

Робот выполняет команды:

- повернуть налево
- повернуть направо
- сделать шаг вперед
- очистить текущую клетку

Команды должны быть представлены через Command. Очередь команд может содержать обычные объекты команд или callable objects через `std::function`

Маршрут робота должен строиться через выбранную стратегию уборки. Реализовать не менее двух стратегий, например:

- движение по строкам
- выбор ближайшей загрязненной клетки

Стратегию можно выбрать в программе через именованную константу или отдельную переменную

Работа робота завершается, когда выбранная стратегия больше не может построить следующую полезную команду или достигнут лимит шагов. Лимит шагов задать именованной константой. Часть загрязненных клеток может остаться неочищенной, если робот не может до них добраться

Робот должен сообщать о событиях. На события должны реагировать несколько observers:

- журнал шагов
- счетчик очищенных клеток
- счетчик ошибок движения

К событиям относятся:

- выполненная команда
- успешное перемещение
- очистка клетки
- попытка выйти за границы карты
- попытка пройти через препятствие
- завершение работы

Программа должна сформировать файл отчета. Имя файла отчета строится из имени входного файла добавлением `_report` перед расширением. Например, для `room.txt` отчет должен быть записан в `room_report.txt`

Отчет должен показывать работу робота по шагам. Для каждого шага вывести карту после выполнения команды, а под картой краткий отчет шага:

- номер шага
- выполненная команда
- позиция робота
- направление робота
- событие или ошибка
- количество очищенных клеток

В конце файла вывести итоговый отчет:

- размер карты
- количество загрязненных клеток в начале
- количество очищенных клеток
- количество оставшихся загрязненных клеток
- количество ошибок движения
- количество выполненных команд
- причина остановки робота

Программа должна корректно обрабатывать:

- запуск без аргумента командной строки
- невозможность открыть файл карты
- пустой файл карты
- строки карты разной длины
- отсутствие начальной позиции робота
- несколько начальных позиций робота
- неизвестный символ карты

## Требования

- Названия переменных, функций, типов и других сущностей программы должны быть осмысленными и записываться на английском языке без транслитерации
- Программа должна читать карту помещения из файла, путь к которому передан через аргумент командной строки
- Размер карты не должен быть зашит в программе
- Программа должна создавать файл отчета с добавлением `_report` к имени входного файла
- В программе должно быть не менее двух стратегий уборки
- В программе должен использоваться Strategy для выбора поведения робота
- В программе должен использоваться Command для действий робота
- В программе должны использоваться observers для событий робота
- В программе должен быть пример использования `std::function` или lambda для команды или обработчика события
- Отчет должен содержать карту и краткий отчет после каждого шага
- В программе должен быть лимит шагов для защиты от бесконечного выполнения
- Программа должна быть грамотно разбита на модули и содержать как минимум один `.hpp` файл и два `.cpp` файла. Допускается использовать больше файлов
- Для заголовочных файлов использовать `#pragma once`
- Программа должна компилироваться и выполняться без ошибок
- Студент должен понимать написанный код, уметь обосновать свое решение и отвечать на вопросы во время защиты лабораторной работы

Минимальный набор операций:

- чтение карты из входного потока
- выбор следующей команды через стратегию уборки
- выполнение команды робота
- уведомление observers о событии
- запись шага робота в отчет
