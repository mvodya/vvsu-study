# Лабораторная работа 16. Structural patterns

## Задание

Разработать программу для агрегатора прогноза погоды

Программа получает данные от нескольких условных погодных сервисов. Реальный HTTP или API использовать не требуется. Ответы сервисов находятся в текстовых файлах разных форматов

Пути к файлам передаются через аргументы командной строки

Пример запуска:

```text
./weather_aggregator service_a.txt service_b.txt service_c.txt
```

Поддержать три формата входных данных

Service A:

```text
city=Vladivostok
temperature_c=18.5
wind_ms=6.2
humidity=72
```

Service B:

```text
Vladivostok;65.3;13.9;72
```

Поля Service B идут в порядке:

```text
city;temp_f;wind_mph;humidity
```

Service C:

```text
name: Vladivostok
temp_kelvin: 291.65
wind_kmh: 22.3
humidity_percent: 72
```

Внутри программы прогноз должен быть представлен в едином формате:

- город
- температура в градусах Цельсия
- скорость ветра в метрах в секунду
- влажность в процентах
- имя источника данных

Для работы с сервисами создать общий интерфейс weather provider. Для каждого формата входных данных реализовать отдельный Adapter, который приводит данные сервиса к общему интерфейсу

Поверх providers добавить decorators:

- logging decorator записывает факт запроса прогноза
- caching decorator возвращает уже загруженный прогноз при повторном запросе того же города
- validation decorator проверяет разумные диапазоны значений

Клиентский код должен работать через Facade. Facade принимает список providers, запрашивает прогнозы по городу, отбрасывает некорректные результаты и формирует общий отчет

Для каждого города, найденного во входных данных, программа должна вывести:

- прогнозы всех доступных сервисов
- среднюю температуру
- среднюю скорость ветра
- среднюю влажность
- список источников, которые вернули корректные данные
- список ошибок чтения или проверки данных

Итоговый отчет вывести в консоль и сохранить в файл `weather_report.txt`

Программа должна корректно обрабатывать:

- запуск без аргументов командной строки
- невозможность открыть входной файл
- неизвестный формат файла
- поврежденные строки
- отсутствующее обязательное поле
- некорректное числовое значение
- значения вне разумного диапазона

## Требования

- Названия переменных, функций, типов и других сущностей программы должны быть осмысленными и записываться на английском языке без транслитерации
- Программа должна читать пути к файлам погодных сервисов из аргументов командной строки
- В программе должен быть общий интерфейс weather provider
- Для каждого из трех форматов входных данных должен быть реализован Adapter
- В программе должны быть logging, caching и validation decorators для weather provider
- Клиентский код должен получать прогнозы через Facade
- Facade должен скрывать создание цепочки providers и decorators от основной логики программы
- Внутренняя модель прогноза должна использовать единые единицы измерения: градусы Цельсия и метры в секунду
- Программа должна сохранять итоговый отчет в файл `weather_report.txt`
- Программа должна быть грамотно разбита на модули и содержать как минимум один `.hpp` файл и два `.cpp` файла. Допускается использовать больше файлов
- Для заголовочных файлов использовать `#pragma once`
- Программа должна компилироваться и выполняться без ошибок
- Студент должен понимать написанный код, уметь обосновать свое решение и отвечать на вопросы во время защиты лабораторной работы

Минимальный набор операций:

- чтение прогноза через provider
- адаптация данных внешнего формата к внутренней модели
- декорирование provider дополнительным поведением
- получение прогноза через Facade
- формирование агрегированного отчета
