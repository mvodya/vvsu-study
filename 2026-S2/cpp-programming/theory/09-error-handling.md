## Результат операции и ошибка

Функция задает допустимые входные данные, результат и способ сообщить о проблеме. Выбор механизма зависит от смысла ситуации

| Ситуация                                     | Механизм                                                 |
| -------------------------------------------- | -------------------------------------------------------- |
| Поиск завершился без совпадения              | Пустой `std::optional<T>`                                |
| Ошибочная запись в наборе данных             | Причина ошибки и продолжение обработки остальных записей |
| Операция прервана из-за недоступного ресурса | Исключение и обработчик на подходящем уровне             |
| Нарушено внутреннее предположение алгоритма  | `assert` в диагностической сборке                        |

Ошибки входных данных проверяются во время выполнения. Внутренние предположения описывают состояние, которое должен обеспечить собственный код программы

## throw, try и catch

`throw` создает объект исключения и начинает поиск подходящего обработчика. `try` задает защищенный блок. `catch` объявляет обработчик конкретного типа исключения

```cpp
try {
  std::cout << "before\n";
  throw 7;
  std::cout << "after\n";
} catch (int code) {
  std::cout << "caught " << code << '\n';
}
std::cout << "continue\n";
```

Фрагмент выполняется внутри функции, для вывода нужен `<iostream>`. Результат:

```text
before
caught 7
continue
```

После `throw` управление переходит к обработчику. Строка с `after` пропускается. После обычного завершения `catch` выполнение продолжается за всей конструкцией `try` и `catch`

Число здесь показывает выбор обработчика по типу. Для сообщений с причиной подходят стандартные классы исключений

## Стандартные классы исключений

`std::exception` из `<exception>` задает общий интерфейс стандартных исключений. Метод `what()` возвращает текстовое описание как `const char*`

| Тип                        | Заголовок     | Пример применения                  |
| -------------------------- | ------------- | ---------------------------------- |
| `std::invalid_argument`    | `<stdexcept>` | Недопустимое значение аргумента    |
| `std::out_of_range`        | `<stdexcept>` | Индекс за пределами контейнера     |
| `std::runtime_error`       | `<stdexcept>` | Сбой операции во время выполнения  |
| `std::bad_alloc`           | `<new>`       | Ошибка выделения памяти            |
| `std::bad_optional_access` | `<optional>`  | Вызов `value()` у пустого optional |

```cpp
int checkedVolume(int value) {
  if (value < 0 || value > 100)
    throw std::invalid_argument{"Volume must be in 0..100"};
  return value;
}
```

```cpp
try {
  std::cout << checkedVolume(120) << '\n';
} catch (const std::exception &error) {
  std::cerr << error.what() << '\n';
}
```

Нужны `<stdexcept>`, `<exception>` и `<iostream>`. Перехват по `const` ссылке сохраняет динамический тип объекта исключения и позволяет получить его сообщение через виртуальный `what()`

Указатель от `what()` связан с lifetime объекта исключения. Для сохранения сообщения за пределами обработчика его копируют в `std::string`

## Поиск обработчика

Обработчик выбирается по типу объекта исключения. Подходит точный тип или доступный однозначный базовый тип. Обычные арифметические преобразования при выборе `catch` отсутствуют: `catch (double)` пропускает исключение типа `int`

Обработчики одного `try` проверяются сверху вниз. Обработчик производного типа размещают перед обработчиком базового типа

```cpp
try {
  std::cout << std::stoi(text) << '\n';
} catch (const std::invalid_argument &error) {
  std::cerr << "Expected an integer: " << error.what() << '\n';
} catch (const std::out_of_range &error) {
  std::cerr << "Integer is too large: " << error.what() << '\n';
} catch (const std::exception &error) {
  std::cerr << error.what() << '\n';
}
```

Фрагмент использует `std::string text`, нужны `<string>`, `<stdexcept>`, `<exception>` и `<iostream>`. `std::stoi` выбрасывает `invalid_argument`, когда преобразование числа невозможно, и `out_of_range`, когда результат выходит за допустимый диапазон

`catch (...)` перехватывает исключение любого типа и располагается последним. Для вывода конкретной причины удобен обработчик с именованным объектом

Если текущая функция передает исключение дальше, поиск продолжается по цепочке вызовов до внешнего `try`. Отсутствие подходящего обработчика приводит к вызову `std::terminate`, который по умолчанию аварийно завершает программу

## Свой тип ошибки и повторный throw

Собственный класс позволяет отделить ошибки определенной операции. Наследование от `std::runtime_error` сохраняет хранение сообщения и интерфейс `what()`

```cpp
class ConfigError : public std::runtime_error {
public:
  explicit ConfigError(const std::string &message)
      : std::runtime_error{message} {}
};
```

В обработчике `throw;` повторно передает текущее исключение с исходным динамическим типом

```cpp
try {
  throw ConfigError{"Missing width"};
} catch (const ConfigError &error) {
  std::cerr << "Config: " << error.what() << '\n';
  throw;
}
```

Внешний обработчик должен принять повторно переданное исключение. Вызов `throw;` при отсутствии обрабатываемого исключения приводит к `std::terminate`. Запись `throw error;` создает новый объект из выражения и при базовом статическом типе может привести к slicing

## Строгий разбор значения

Функции преобразования строк могут принять корректный числовой префикс. Позиция окончания преобразования позволяет проверить всю строку

```cpp
int parseWidth(const std::string &text) {
  std::size_t used = 0;
  int width = std::stoi(text, &used);
  if (used != text.size())
    throw std::invalid_argument{"Unexpected suffix"};
  if (width < 1 || width > 4096)
    throw std::out_of_range{"Width must be in 1..4096"};
  return width;
}
```

Нужны `<string>` и `<stdexcept>`. Строка `640px` дает ошибку суффикса, `0` дает ошибку диапазона. В этом варианте начальные пробелы и знак обрабатываются по правилам `std::stoi`

Синтаксис конкретного формата задается отдельно. Проверка количества полей, разделителей и диапазонов выполняется до добавления результата в общую коллекцию

## Повторный ввод

Обработчик внутри цикла позволяет запросить новое значение после ошибки. `std::getline` читает очередную строку и проверяется отдельно от преобразования

```cpp
std::string text;
while (std::cout << "Width: " && std::getline(std::cin, text)) {
  try {
    int width = parseWidth(text);
    std::cout << "Accepted: " << width << '\n';
    break;
  } catch (const std::exception &error) {
    std::cerr << error.what() << '\n';
  }
}
```

При ошибке цикл переходит к следующему запросу. Успешное чтение значения завершает цикл через `break`. Завершение входного потока останавливает цикл по условию

Потоки по умолчанию сообщают об ошибках через флаги состояния. Проверка `if (stream)` проверяет успешность операции. Метод `exceptions()` позволяет включить исключения для выбранных флагов

## Граница обработки ошибки

Положение `try` определяет, какую операцию программа сможет продолжить. Для обработки независимых записей обработчик размещается внутри цикла

```cpp
std::vector<int> widths;
std::vector<std::string> errors;
for (const auto &text : lines) {
  try {
    widths.push_back(parseWidth(text));
  } catch (const std::invalid_argument &error) {
    errors.push_back(error.what());
  } catch (const std::out_of_range &error) {
    errors.push_back(error.what());
  }
}
```

`lines` имеет тип `std::vector<std::string>`, нужен `<vector>`. Ошибка значения добавляется в список, затем начинается следующая итерация. Ошибка выделения памяти передается внешнему уровню, который может завершить всю операцию

Для нескольких файлов тот же принцип применяется на уровне файла: каждый вызов импорта получает собственный `try`, а ошибка записи обрабатывается глубже, внутри импорта

## Stack unwinding и RAII

При переходе от `throw` к найденному обработчику вызываются деструкторы созданных локальных объектов покидаемых блоков. Порядок обратен завершению их создания. Этот процесс называется stack unwinding

```cpp
struct Trace {
  const char *name;
  ~Trace() { std::cout << name << '\n'; }
};

void work() {
  Trace first{"first"};
  Trace second{"second"};
  throw std::runtime_error{"Stopped"};
}
```

При вызове `work()` внутри внешнего `try` сначала выводится `second`, затем `first`, затем начинает работать обработчик. Нужны `<iostream>` и `<stdexcept>`

RAII связывает ресурс с объектом. Файловый поток закрывает файл своим деструктором при обычном выходе и при stack unwinding

```cpp
void readSettings(const std::string &path) {
  std::ifstream input{path};
  if (!input) throw ConfigError{"Cannot open " + path};
  std::string line;
  while (std::getline(input, line)) {
    parseWidth(line);
  }
  if (input.bad()) throw ConfigError{"Cannot read " + path};
}
```

Для потока нужен `<fstream>`. Если конструктор объекта завершается исключением, вызываются деструкторы его уже созданных полей и базовых частей. Деструктор самого объекта с незавершенным конструктором пропускается

При исключении без обработчика вызов деструкторов до `std::terminate` зависит от реализации. Для освобождения ресурсов при ожидаемой ошибке нужен путь к подходящему обработчику

## assert и внутренние предположения

`assert` из `<cassert>` проверяет условие во время выполнения. Ложное условие выводит диагностическое сообщение и вызывает `abort`. Такой сбой завершает процесс, обычный `catch` обрабатывает исключения, созданные через механизм `throw`

```cpp
int middleIndex(int left, int right) {
  assert(0 <= left && left <= right);
  return left + (right - left) / 2;
}
```

Здесь вызывающий алгоритм обязан передать упорядоченные границы. Проверка помогает обнаружить ошибку в его реализации. Проверка пользовательского ввода выполняется до вызова алгоритма

Если `NDEBUG` определен перед подключением `<cassert>`, проверка отключается вместе с вычислением ее выражения

```bash
clang++ -std=c++20 -DNDEBUG main.cpp -o app
```

Внутри `assert` размещают проверку без обязательных побочных эффектов. Изменение состояния выполняют отдельным выражением

```cpp
queue.push_back(7);
assert(!queue.empty());
```

Фрагмент использует `std::vector<int> queue`. При отключении проверок добавление элемента сохраняется. При `abort` обычный выход из scope и вызовы локальных деструкторов пропускаются

## std::optional и отсутствие значения

`std::optional<T>` из `<optional>` содержит объект `T` или пустое состояние. Это подходит для результата поиска и необязательного поля

```cpp
struct Book {
  std::string title;
  std::optional<int> publicationYear;
};

Book known{"Algorithms", 2020};
Book draft{"Notes", std::nullopt};
```

Нужны `<string>` и `<optional>`. Значение `std::nullopt` обозначает отсутствие данных. Инициализация `std::optional<int> count{0}` создает присутствующее значение `0`

| Операция                             | Поведение                                                            |
| ------------------------------------ | -------------------------------------------------------------------- |
| `if (value)` или `value.has_value()` | Проверка наличия значения                                            |
| `*value`, `value->member`            | Доступ при выполненном условии наличия значения                      |
| `value.value()`                      | Доступ с исключением `std::bad_optional_access` при пустом состоянии |
| `value.value_or(fallback)`           | Значение или запасной вариант                                        |
| `value.reset()`                      | Вызов деструктора хранимого значения и переход в пустое состояние    |
| `value.emplace(args...)`             | Создание нового значения внутри optional                             |

В C++20 обращение через `*` или `->` к пустому optional приводит к undefined behavior. Сначала проверяют наличие значения. Аргумент `value_or` вычисляется по обычным правилам вызова функции, поэтому для дорогого запасного вычисления подходит явное ветвление

## Поиск с optional

Функция возвращает значение при совпадении и `std::nullopt` после завершения поиска

```cpp
std::optional<Book> findBook(const std::vector<Book> &books,
                             const std::string &title) {
  for (const auto &book : books)
    if (book.title == title) return book;
  return std::nullopt;
}
```

```cpp
if (auto book = findBook(books, "Notes")) {
  std::cout << book->title << '\n';
  std::cout << book->publicationYear.value_or(0) << '\n';
} else {
  std::cout << "Book not found\n";
}
```

`books` имеет тип `std::vector<Book>`, нужны `<vector>` и `<iostream>`. Возвращаемый optional владеет копией найденной книги. В этом выводе `0` выбран как обозначение неизвестного года

Пустой optional сообщает только об отсутствии значения. Подробную причину ошибки можно передать отдельным типом результата

## Гарантии при исключениях

Гарантия исключений описывает состояние операции после сбоя

| Гарантия              | Состояние после исключения                                         |
| --------------------- | ------------------------------------------------------------------ |
| Базовая               | Инварианты сохранены, ресурсы освобождены, данные могут измениться |
| Строгая               | Состояние соответствует состоянию до вызова                        |
| Отсутствие исключений | Операция завершается без передачи исключения вызывающему коду      |

Проверки и потенциально ошибочные вычисления удобно выполнять до изменения основного состояния. Например, сначала разобрать новую настройку, затем присвоить результат

```cpp
void updateWidth(int &width, const std::string &text) {
  int next = parseWidth(text);
  width = next;
}
```

При исключении из `parseWidth` исходная ширина сохраняется. Обычное присваивание `int` завершает изменение

Спецификатор `noexcept` задает запрет выхода исключения из функции. Нарушение приводит к `std::terminate`. Он подходит для операций, которые способны выполнить этот контракт

Деструкторы по умолчанию обычно имеют `noexcept` с учетом базовых частей и полей. Выход второго исключения из деструктора при stack unwinding приводит к `std::terminate`. Ошибки освобождения ресурса обрабатывают внутри операции либо сообщают через отдельный явный метод завершения

## std::expected в C++23

`std::expected<T, E>` из `<expected>` хранит успешный результат `T` или объект ошибки `E`. `std::unexpected` создает ошибочный результат. Проверка состояния определяет доступную часть: `value()` для результата, `error()` для ошибки

Этот тип подходит для функции разбора, которой нужно вернуть конкретную причину отказа. Его использование требует режима C++23 и поддержки со стороны стандартной библиотеки
