## Перегрузка функций

Перегрузка объединяет несколько функций с одним именем и разными списками параметров. Отличаться могут количество, типы и порядок параметров. В главе 01 использовались отдельные перегрузки, здесь рассматривается выбор между ними

```cpp
void print(int value) { std::cout << "int: " << value << '\n'; }
void print(double value) { std::cout << "double: " << value << '\n'; }
void print(int value, int width) { std::cout << std::setw(width) << value; }
```

Для примера нужны `<iostream>` и `<iomanip>`. Вызовы `print(7)`, `print(7.5)` и `print(7, 4)` выбирают разные функции. Имя описывает одну операцию, параметры - варианты ее применения

Объявления `int read();` и `double read();` в одной области вызывают ошибку компиляции: для перегрузки требуется различие параметров. Имена параметров могут свободно меняться между declaration и definition одной функции

## Выбор перегрузки

Overload resolution - выбор функции среди перегрузок. Компилятор собирает видимые объявления, проверяет возможность передать аргументы и сравнивает требуемые преобразования

```cpp
void select(int) { std::cout << "int\n"; }
void select(double) { std::cout << "double\n"; }

// Внутри функции:
short small{3};
select(3);     // int
select(3.0);   // double
select(small); // int
select(3.0f);  // double
```

Для примера нужен `<iostream>`. `short` повышается до `int`, `float` повышается до `double`. Эти преобразования называются promotions

Для обычных числовых аргументов основные предпочтения выглядят так:

| Вариант                           | Пример                                | Предпочтение      |
| --------------------------------- | ------------------------------------- | ----------------- |
| Точное совпадение                 | `int` -> `int`                        | выше              |
| Promotion                         | `short` -> `int`, `float` -> `double` | затем             |
| Другое стандартное преобразование | `int` -> `double`, `double` -> `int`  | затем             |
| Пользовательское преобразование   | значение -> объект через конструктор  | после стандартных |

Это рабочая схема для приведенных примеров. Полные правила также учитывают привязку ссылок и другие свойства параметров. При нескольких аргументах требуется единственная лучшая подходящая функция с учетом всех аргументов

### Неоднозначный вызов

```cpp
void choose(long) {}
void choose(double) {}

// Внутри функции:
choose(1); // ошибка компиляции: ambiguous
```

Оба преобразования `int` имеют одинаковый ранг. Явное задание нужного типа устраняет неоднозначность:

```cpp
choose(1L);
choose(1.0);
```

Похожая ситуация возникает с аргументами по умолчанию:

```cpp
void save(int) {}
void save(int, bool = false) {}

// Внутри функции:
save(3); // ошибка компиляции: ambiguous
```

Один аргумент подходит обеим функциям. Интерфейс следует строить так, чтобы каждый ожидаемый вызов имел единственный результат выбора

## Перегрузки и ссылки

Ссылочные параметры позволяют различать доступ к изменяемому и константному объекту:

```cpp
void inspect(std::string& text) { text += "!"; }
void inspect(const std::string& text) { std::cout << text << '\n'; }

// Внутри функции:
std::string first{"Atlas"};
const std::string second{"Guide"};
inspect(first);  // string&
inspect(second); // const string&
```

Для примера нужны `<string>` и `<iostream>`. Изменяемый lvalue выбирает `std::string&`. Константный объект привязывается к `const std::string&`. Временная строка также может привязаться к `const std::string&` на время вызова

Параметры `int value` и `const int value` описывают один тип параметра функции: верхнеуровневый `const` относится к локальной копии. У ссылок `int&` и `const int&` доступ к исходному объекту различается, поэтому такие перегрузки допустимы

Перегрузки по `T&` и `T&&` используются в копировании и перемещении из главы 03. Именованная переменная является lvalue, `std::move(value)` предоставляет xvalue для выбора подходящей перегрузки

## Неявные числовые преобразования

Неявное преобразование выполняется при передаче аргумента, присваивании, возврате результата и вычислении выражения, если контекст требует другого типа

```cpp
int count{7};
double value = count;
int whole = 3.8; // 3
```

Переход к целому отбрасывает дробную часть в направлении нуля. Для вещественного числа вне диапазона целевого целого типа такое преобразование приводит к undefined behavior. Перед преобразованием требуется проверка диапазона и конечности

Целые числа большого размера могут терять точность при переходе к вещественному типу. Преобразование к типу с другим диапазоном требует отдельного решения о допустимых значениях

### Типы в выражении

```cpp
int total{7};
int count{2};
double first = total / count;                      // 3.0
double second = static_cast<double>(total) / count; // 3.5
```

В первом выражении сначала выполняется целочисленное деление. Во втором левый операнд имеет тип `double`, правый приводится к нему, деление становится вещественным. Тип переменной результата начинает участвовать только при инициализации после вычисления правой части

Для примеров деления требуется ненулевой знаменатель. При смешивании signed и unsigned результат общего преобразования может оказаться unsigned. Например, для `int value = -1;` выражение `value < 1u` дает `false`. Сравнение выполняется после преобразования `value` к `unsigned int`

## Явное преобразование и narrowing

`static_cast<T>(expression)` выражает явное преобразование к типу `T`:

```cpp
double duration{12.8};
int seconds = static_cast<int>(duration); // 12
```

`static_cast` выражает намерение автора. Проверка диапазона остается отдельной операцией

Инициализация через `{}` выявляет narrowing - сужающие преобразования:

```cpp
double value{3.8};
int count{value}; // ошибка компиляции: narrowing
```

Для намеренного отбрасывания дробной части после проверки значения используется `int count{static_cast<int>(value)};`. Фигурные скобки проверяют правила narrowing, включая ограничения на целочисленные константы и представимость значений

### Проверка диапазона

`std::numeric_limits<int>` из `<limits>` предоставляет границы целого типа. Для обычного 32-битного `int` обе границы точно представимы в `double`:

```cpp
double value{12.8};
if (std::isfinite(value) &&
    value >= std::numeric_limits<int>::lowest() &&
    value <= std::numeric_limits<int>::max()) {
    int whole = static_cast<int>(value);
    std::cout << whole << '\n';
}
```

Нужны `<cmath>`, `<limits>` и `<iostream>`. Проверка консервативна: принимаются конечные значения между границами типа. Для другого сочетания исходного и целевого типов требуется учитывать точность представления самих границ

## Пользовательские преобразования

В главе 02 введены converting constructor и `explicit`. Здесь они рассматриваются как участники выбора перегрузки. Конструктор получает исходное значение и создает объект целевого типа:

```cpp
class Length {
    double meters;
public:
    explicit Length(double meters) : meters{meters} {}
    double value() const { return meters; }
};
void show(Length length) { std::cout << length.value() << '\n'; }
```

Для примера нужен `<iostream>`. Вызов `show(Length{2.5})` явно создает длину. Вызов `show(2.5)` завершается ошибкой компиляции из-за `explicit`. Удаление `explicit` разрешает этот неявный переход

Conversion operator задает преобразование из объекта класса:

```cpp
class Count {
    int value;
public:
    explicit Count(int value) : value{value} {}
    explicit operator int() const { return value; }
};

// Внутри функции:
Count count{12};
int raw = static_cast<int>(count);
```

Для одной неявной последовательности преобразований разрешено максимум одно пользовательское преобразование. Цепочку из двух таких переходов выражают явными промежуточными объектами

### Преобразование единиц

Разным единицам измерения можно сопоставить отдельные типы. Это позволяет выбирать преобразование по типу аргумента:

```cpp
struct Meters { double value; };
struct Feet { double value; };

Meters toMeters(Meters length) { return length; }
Meters toMeters(Feet length) { return {length.value * 0.3048}; }

// Внутри функции:
Meters first = toMeters(Meters{2.0});
Meters second = toMeters(Feet{10.0});
```

Смена числового типа сохраняет смысл единицы измерения. Смена единицы требует формулы преобразования. Функция с предметным именем делает эту операцию видимой в коде

## Связь с перегрузкой операторов

Перегрузка операторов рассмотрена в главе 02. Выбор `operator+` или `operator<<` также использует типы операндов и допустимые преобразования. Здесь применяются те же требования к однозначности вызова и контролю неявных преобразований
