## Контейнер, итератор и алгоритм

Контейнер владеет набором элементов и управляет их временем жизни. Итератор обозначает позицию в последовательности. Алгоритм получает диапазон через итераторы и выполняет операцию над элементами

```cpp
std::vector<int> values{8, 3, 5};
auto found = std::find(values.begin(), values.end(), 3);
if (found != values.end()) std::cout << *found << '\n';
```

Нужны `<vector>`, `<algorithm>` и `<iostream>`. `std::find` возвращает позицию первого совпадения или конец диапазона. Контейнер задает хранение, алгоритм использует доступные операции итератора

Последовательные контейнеры сохраняют заданный порядок элементов. Выбор контейнера определяет стоимость доступа, вставки, удаления и правила сохранения ссылок

## std::vector: динамический массив

`std::vector<T>` из `<vector>` хранит элементы непрерывно в памяти. Доступ по индексу занимает постоянное время. Для `std::vector<bool>` действует специальная реализация, разобранная в главе 08

```cpp
std::vector<int> values{10, 20, 30};
values.push_back(40);
values[1] = 25;
std::cout << values.at(2) << '\n';
values.pop_back();
```

`push_back` добавляет элемент в конец, `pop_back` вызывает деструктор последнего элемента и уменьшает размер. `operator[]` требует допустимый индекс. `at()` проверяет границу и при ошибке выбрасывает `std::out_of_range`

`front()` и `back()` возвращают ссылки на первый и последний элементы. Вызовы требуют присутствия элементов. `empty()` проверяет пустоту, `size()` дает количество элементов

```cpp
if (!values.empty()) {
  std::cout << values.front() << ' ' << values.back() << '\n';
}
```

Контейнер хранит объекты по значению. Копирование обычного `vector<T>` копирует элементы, поэтому изменение копии сохраняет исходный набор. Возможность копирования зависит от типа `T`

## Создание элементов

Круглые скобки позволяют задать количество и начальное значение. Фигурные скобки могут выбрать конструктор со списком элементов

```cpp
std::vector<int> zeros(3);       // 0, 0, 0
std::vector<int> copies(3, 7);   // 7, 7, 7
std::vector<int> pair{3, 7};     // 3, 7
```

`emplace_back` передает аргументы конструктору элемента в конце последовательности

```cpp
struct Point {
  int x, y;
  Point(int x, int y) : x{x}, y{y} {}
};
std::vector<Point> points;
points.emplace_back(2, 5);
```

При необходимости увеличения буфера уже существующие элементы также перемещаются или копируются. Тип нового элемента определяется параметром контейнера

## size, capacity, reserve и resize

`size()` - число существующих элементов. `capacity()` - вместимость выделенного буфера. Инвариант: `size() <= capacity()`

```cpp
std::vector<int> values;
values.reserve(8);
std::cout << values.size() << '\n'; // 0
values.resize(3);
std::cout << values.size() << '\n'; // 3
values[0] = 42;
```

`reserve(8)` обеспечивает вместимость как минимум для восьми элементов. При прежней вместимости от восьми буфер сохраняется. Размер последовательности остается прежним

`resize(3)` устанавливает размер равным трем. При росте создаются элементы, при уменьшении вызываются деструкторы удаляемых элементов. Для новых `int` в этом примере используется `0`

Доступ по индексу разрешен только в пределах `size()`. Зарезервированная память за последним элементом остается вне диапазона доступа

`clear()` удаляет все элементы и сохраняет capacity. `shrink_to_fit()` запрашивает сокращение буфера, выполнение запроса зависит от реализации

## Рост и сложность операций

Если новый размер превышает capacity, `vector` выделяет другой буфер и переносит элементы. Это называется перераспределением памяти, или reallocation

Один `push_back` при перераспределении требует линейной работы по числу элементов. Для последовательности добавлений стоимость одного добавления амортизированно постоянна: общая работа распределяется по всем добавлениям

Коэффициент роста зависит от реализации. При известном ожидаемом количестве элементов один предварительный `reserve` сокращает число перераспределений

Вставка в середину сдвигает последующие элементы вправо, удаление - влево. Стоимость зависит от числа затронутых элементов

```cpp
std::vector<int> values{10, 30};
auto inserted = values.insert(values.begin() + 1, 20);
std::cout << *inserted << '\n'; // 20
values.erase(values.begin());   // 20, 30
```

`insert` вставляет перед переданной позицией и возвращает итератор вставленного элемента. `erase` возвращает позицию следующего элемента или `end()`

## Итераторы и диапазон

`begin()` указывает на первый элемент, `end()` обозначает позицию сразу после последнего. Диапазон записывают как `[begin, end)`: правая граница исключена

```cpp
std::vector<int> values{2, 4, 6};
for (auto it = values.begin(); it != values.end(); it++) {
  *it += 1;
}
```

Разыменование `*it` дает доступ к элементу. `it++` переходит к следующему. `end()` используется для сравнения, разыменование требует позиции существующего элемента. У пустого контейнера `begin() == end()`

```cpp
for (auto it = values.cbegin(); it != values.cend(); it++) {
  std::cout << *it << '\n';
}
```

`cbegin()` и `cend()` дают const iterators. Через них доступно чтение элементов. `const auto it = values.begin()` фиксирует сам итератор, доступ к элементу определяется типом итератора

Для обычного обхода подходит range-for. Важен выбор переменной цикла

```cpp
for (auto value : values) {
  value += 1;                              // меняется локальная копия
  std::cout << value << ' ';
}
for (auto &value : values) value += 1;       // меняются элементы
for (const auto &value : values) std::cout << value << '\n';
```

Итераторы `vector`, `array` и `deque` поддерживают арифметику вроде `it + 2`. Итератор `list` перемещается шагами вперед и назад. Для перехода на заданное число шагов подходит `std::advance` из `<iterator>`

## Удаление при обходе

После удаления текущего элемента обход продолжают с итератора, который вернул `erase`

```cpp
std::vector<int> values{1, 0, 0, 3};
for (auto it = values.begin(); it != values.end();) {
  if (*it == 0) it = values.erase(it);
  else it++;
}
```

После удаления следующий элемент занимает текущую позицию. Дополнительный шаг в этой ветви пропустил бы его проверку. При обычном проходе счетчик продвигается один раз

Последовательные удаления из середины большого вектора могут дать квадратичную суммарную работу. В C++20 для удаления по значению доступна `std::erase(values, 0)`, которая выполняет обработку за линейное время

## Invalidation: действительность итераторов

Изменение контейнера может сделать сохраненный итератор, указатель или ссылку недействительными. Правила зависят от контейнера и операции

Для `vector`:

| Операция                      | Что становится недействительным                                   |
| ----------------------------- | ----------------------------------------------------------------- |
| Перераспределение памяти      | Все итераторы, указатели и ссылки, включая прежний `end()`        |
| Вставка при сохранении буфера | Позиции вставки и после нее, включая прежний `end()`              |
| Удаление элемента             | Позиции удаляемого элемента и после него, включая прежний `end()` |
| `clear()`                     | Все позиции элементов и прежний `end()`                           |

```cpp
std::vector<int> values{10, 20};
auto it = values.begin();
std::cout << *it << '\n';
values.reserve(values.capacity() + 1);
it = values.begin();
std::cout << *it << '\n';
```

Успешный `reserve` с аргументом больше прежней capacity гарантирует перераспределение. После него старое значение `it` заменяется новым итератором. Пример намеренно получает новую позицию перед следующим обращением

Обращение через недействительную позицию приводит к undefined behavior. Совпадение напечатанных адресов или сохраненное старое значение памяти оставляет такое обращение ошибочным

Индекс сохраняет число, поэтому его можно использовать после перераспределения для повторного получения элемента. Вставка и удаление перед этим индексом меняют соответствие между индексом и конкретным объектом. Для устойчивой идентичности объекта применяют отдельный идентификатор

Во время range-for итераторы обхода скрыты синтаксисом. Изменение контейнера должно учитывать их действительность. Один из приемов - накопить новые элементы отдельно и добавить их после завершения обхода

## std::array: фиксированное число элементов

`std::array<T, N>` из `<array>` хранит `N` элементов внутри самого объекта. Размер является частью типа, элементы расположены непрерывно

```cpp
std::array<int, 4> channels{};
channels[0] = 512;
channels.fill(100);
std::cout << channels.size() << ' ' << channels.at(0) << '\n';
```

Нулевая инициализация `{}` задает нули для всех `int`. `fill` присваивает значение всем элементам. Размер остается постоянным, операции добавления и удаления элементов отсутствуют

`data()` дает указатель на первый элемент непрерывного набора. Такой интерфейс есть также у обычного `vector<T>`. Срок использования указателя ограничен lifetime элементов и правилами invalidation

`std::array<T, 0>` представляет пустой набор. Проверка `empty()` позволяет отделить его от массива с доступными первым и последним элементами

## std::deque: рост с двух концов

`std::deque<T>` из `<deque>` предоставляет добавление и удаление с обоих концов и доступ по индексу за постоянное время. Типичная реализация хранит элементы в нескольких блоках памяти

```cpp
std::deque<std::string> jobs{"render", "save"};
jobs.push_front("urgent");
jobs.push_back("cleanup");
while (!jobs.empty()) {
  std::cout << jobs.front() << '\n';
  jobs.pop_front();
}
```

Нужны `<deque>`, `<string>` и `<iostream>`. Новая срочная задача попадает в начало, обычная - в конец. Обработка удаляет завершенную задачу с начала

У `deque` отсутствуют `capacity()`, `reserve()` и общий непрерывный буфер через `data()`. Доступ по индексу использует внутреннюю структуру блоков

Вставка на любом конце делает все сохраненные итераторы недействительными, ссылки на существующие элементы сохраняются. Вставка в середину делает недействительными итераторы и ссылки на элементы

При удалении первого элемента с сохранением последнего недействительными становятся только позиции удаленного элемента. Удаление последнего дополнительно меняет `end()`. Удаление из середины делает недействительными все итераторы и ссылки

## std::list: связанная последовательность

`std::list<T>` из `<list>` организует элементы как двусвязную последовательность узлов. Узел связан с предыдущим и следующим. Доступ к произвольной позиции требует прохода по связям

```cpp
std::list<std::string> history{"open", "edit", "save"};
auto current = history.begin();
current++;
history.insert(current, "autosave");
std::cout << *current << '\n'; // edit
history.erase(current);
```

Нужны `<list>`, `<string>` и `<iostream>`. Вставка и удаление одного элемента по готовому итератору выполняются за постоянное время. Поиск самого места вставки или удаления может потребовать линейного прохода

Вставка сохраняет итераторы и ссылки на существующие элементы. Удаление делает недействительными только позиции удаленных элементов. Отдельные узлы требуют дополнительной памяти для связей и дают менее плотное размещение данных

Индексирование через `operator[]` у `list` отсутствует. Для переноса существующего узла в другую позицию применяется `splice`

```cpp
std::list<int> order{1, 2, 3};
auto selected = order.begin();
selected++;
order.splice(order.begin(), order, selected); // 2, 1, 3
std::cout << *selected << '\n';             // 2
```

Здесь переносится один узел в том же списке. Значение и итератор сохраняются, порядок меняется. Операция занимает постоянное время

## Выбор контейнера

Пусть `n` - количество элементов. Таблица описывает основные операции для одного элемента

| Операция               | vector               | array             | deque | list                       |
| ---------------------- | -------------------- | ----------------- | ----- | -------------------------- |
| Доступ по индексу      | O(1)                 | O(1)              | O(1)  | Проход O(n)                |
| Добавление в конец     | Амортизированно O(1) | Размер фиксирован | O(1)  | O(1)                       |
| Добавление в начало    | O(n)                 | Размер фиксирован | O(1)  | O(1)                       |
| Вставка в середину     | O(n)                 | Размер фиксирован | O(n)  | O(1) по готовому итератору |
| Последовательный обход | O(n)                 | O(n)              | O(n)  | O(n)                       |

`O(1)` означает независимость количества базовых действий от числа элементов, `O(n)` - линейную зависимость. Время отдельных конструкторов и операций над `T` также влияет на результат

Для динамического набора с частым обходом и индексированием подходит `vector`. Для фиксированного набора - `array`. Очередь с активными обоими концами удобно хранить в `deque`. `list` полезен при частом изменении связей между узлами и необходимости сохранять позиции остальных элементов

Непрерывное размещение обычно помогает последовательному чтению благодаря работе кеша процессора. Одинаковая асимптотика допускает разное реальное время, которое проверяется измерением на выбранных данных
